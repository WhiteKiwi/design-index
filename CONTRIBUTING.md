# Contributing

## Add a reference

1. Verify the canonical page and, for code, its source repository and license.
2. Add the reference to the most specific guide under `references/`.
3. Add or update its entry in `data/references.yml`.
4. Write one useful takeaway and at least one limit. Avoid adjectives without evidence.
5. Check all Markdown links and review the diff for accidental duplication.

## Classification

- `principle`: authoritative guidance or research.
- `system`: tokens, foundations, components, and governance working together.
- `primitive`: behavior-first building blocks.
- `library`: components, blocks, effects, or templates.
- `portfolio`: an individual or studio site used for composition study.
- `workflow`: tools or methods for human/AI design work.

## Adoption states

- `reference`: useful evidence; no adoption decision.
- `candidate`: worth prototyping with real content.
- `approved`: reviewed for a specific product and allowed by its design authority.
- `implemented`: present in production and visually verified.

An item may have different states in different products. This repository defaults to `reference`.
